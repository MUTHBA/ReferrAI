# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

ReferrAI is a standalone referral and commission management platform with integrated AI capabilities. It is **not** a multi-tenant SaaS product. The platform is designed to be demonstrated end-to-end from referral creation through commission payout tracking.

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | React.js |
| Backend | FastAPI (Python) |
| Database | PostgreSQL |
| ORM | SQLAlchemy (async) |
| Migrations | Alembic |
| Auth | JWT (python-jose) |
| ML | Scikit-learn |
| Anomaly Detection | Isolation Forest |
| Embeddings | Sentence Transformers |
| Explainability | SHAP |
| Deployment | Docker / Docker Compose |

## Development Commands

### Backend
```bash
# Install dependencies
cd backend && pip install -r requirements.txt

# Run development server
uvicorn app.main:app --reload --port 8000

# Run all tests
pytest

# Run a single test file
pytest tests/test_referral.py

# Run a single test
pytest tests/test_referral.py::test_create_referral_link

# Apply database migrations
alembic upgrade head

# Create a new migration
alembic revision --autogenerate -m "description"

# Rollback one migration
alembic downgrade -1
```

### Frontend
```bash
# Install dependencies
cd frontend && npm install

# Run development server
npm run dev

# Build for production
npm run build

# Lint
npm run lint
```

### Docker
```bash
# Start all services
docker-compose up --build

# Start in background
docker-compose up -d

# View logs
docker-compose logs -f backend
```

## Architecture Principles

**Clean layered backend:** Routes call Services, Services call Repositories, Repositories call SQLAlchemy models. Business logic must not live in route handlers.

**AI as internal package with graceful degradation:** The AI module (`backend/app/ai/`) is imported directly by the backend, not a separate service. AI scoring is triggered as background tasks after conversions are recorded. If any AI model fails, the exception is caught, `null` scores are stored, and the core platform continues operating uninterrupted. Never block referral tracking or commission calculation on AI availability.

**Config-driven business rules:** Commission percentages, tier thresholds, withdrawal limits, fraud thresholds, and churn thresholds are all stored in the `settings` table and loaded at runtime. Never hardcode these values.

**Audit everything admin-side:** Every settings change and every admin action (payout approval, fraud flag review) must write a row to `audit_logs`.

**`is_synthetic` flag discipline:** All synthetic training data generated by the AI module must be tagged `is_synthetic = true`. Analytical queries and dashboards must exclude synthetic records by default.

## Key Business Rules

- Commission is calculated automatically when a `ReferralConversion` is recorded.
- Withdrawal requests below the configured `wallet.auto_approval_threshold` are auto-approved **unless** the partner has an active `FraudFlag` with status `pending_review`.
- AI models must **never** automatically suspend an account — fraud flags go to an admin review queue only.
- Partner tier upgrades are evaluated automatically when a conversion is recorded; they are not retroactive.
- Attribution models (first-click / last-click) are configurable per the `referral.attribution_model` setting and determine which click is linked to a conversion.

## Environment Variables

See `.env.example` for required variables. Key ones:
- `DATABASE_URL` — PostgreSQL connection string
- `SECRET_KEY` — JWT signing secret
- `ALGORITHM` — JWT algorithm (default: HS256)
- `ACCESS_TOKEN_EXPIRE_MINUTES`
- `FRAUD_ALERT_THRESHOLD` — default score threshold (overridden by settings table)
